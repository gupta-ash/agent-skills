# wiki-strategize

Produce a goal-oriented strategy, strategy-card, inference or plan from accepted cross-source synthesis. On OMP use `/skill:wiki-strategize`; read the [front](SKILL.md) and [goal-output manual](../wiki/docs/user-manual.md#goal-oriented-outputs). The complete goal and other original argument values remain a JSON array, with `--from-pipeline ID` first when supplied.

`wiki/runtime/workflows.py` is the canonical domain registry. The front does not execute an inline model call or publish Markdown itself. Shared `_workflow` owns native admission, state/attempt accounting, cancellation, resume and canonical publication.

## Acceptance boundaries

The vault must explicitly permit Tier C before any worker dispatch. Facts-only policy cannot be bypassed with a different output type, raw-only override or path. Supporting inputs require accepted synthesis, not merely a compilation-shaped page or topic distillation. Missing coverage blocks with a compilation recommendation.

All four output types retain the goal, context, recommendation/conclusion, fully cited reasoning, evidence base, counter-considerations and measurable review triggers. Direct raw fallback must be justified and cannot replace accepted synthesis. Custom strategy paths, protected targets, preimages and supersession behavior remain authoritative. Tier C does not authorize generic hub rewrites or ClickUp actions.

Required review and verification/repair share the original artifact identity and bounded counters. Delivered native FAIL, NO_REVIEW and exhausted gates stop; changing backend, inventing a decision or allocating a new identity does not admit a replacement candidate. Public `resume --decision` selects only an offered persisted answer. Private engineering admission helpers and run-specific exceptions are not shipped.

## Checks and limitations

The [family source README](../wiki/README.md#consumer-checks) describes synthetic policy, citation, publication and recovery consumers. These checks were not run during this edit; no ordinary public plan-generation native PASS, installed activation or successful recovery from semantic FAIL is claimed. Dry-run is read-only planning, not accepted strategy generation. A missing runtime, source evidence or qualified native route fails closed rather than invoking a standalone fallback.
